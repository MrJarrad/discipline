# Interrogate the brief

Operator ruling 2026-09-20, `brief-is-the-lever`: *"nothing that complex about frontend work
that the right and accurate brief and information wouldn't be easy enough for cheaper
models."* The lever is the brief, not the model. Before any dispatch above trivial/small-fix,
the brief is read as the doer would read it — pointers followed, nothing assumed — and
answered against a fixed set. Findings fix the brief; only then does the lane open.

## The fixed question set

1. Can every contract item be enumerated from the brief and its pointers alone?
2. Which numbers have no source or knob?
3. Which mechanisms are unnamed?
4. Where would the doer be forced to assume?
5. Is the done-when measurable at the operator's framing?
6. Is there exactly one contract unit?
7. Which named skills are missing for the domain?

## Who runs it

**Above trivial/small-fix:** a cheap agent (`haiku`, read-only, findings only — never edits,
never `Agent`s further). **Trivial/small-fix:** the parent, inline.

Interrogator brief template:

```
Read <brief path/pasted brief> and its pointers only, as the doer would. Answer the seven
questions in `dispatch-brief/references/INTERROGATE.md` § The fixed question set. Findings
only, one line each, no fixes, no opinion beyond the question asked.
```

## Recording the result

Findings fix the brief before dispatch. The brief carries:

```markdown
## Interrogated
<finding summary, fixes applied> | or: "inline, clear"
```

A brief dispatched with no `## Interrogated` field is malformed — the same footing as a
brief that restates the contract instead of pointing at it.
