# Mac jobs — review-first jobs and repo checkouts

The queue itself (filing, `mac-job-check.mjs`, the no-background line) is `cloud-dispatch` § Mac-only work; the runner is vault `estate/mac-queue/`.

- **A job that needs review first is filed in `queue/mac/review/`**: the runner reads `review/` on origin/main only, so it runs once its PR merges, never before (DISC-233: a `pending/` job on a `claude/*` branch ran before its review).
- **A job brief that builds or tests a repo** clones it fresh into a temp tree (never the operator's checkout: an uncommitted edit there stopped a job), names the commit it needs and checks the remote head carries it before queueing (`git ls-remote`), checks out with `git fetch origin <sha>` then `git worktree add <dir> FETCH_HEAD`, and frees ports with the macOS form `lsof -ti tcp:A -ti tcp:B` (s45, DISC-230).
- **A job that needs the operator's login is queued only after he signs in and confirms** (s67: two Safari runs measured the Access login page, then a signed-out Safari). The ask is a queue row: what to sign into, where, and "say done".
- **An account write or a repo clone the cloud refuses is a review-first Mac job at once** (s70: a wrangler write and a private figma-plugins clone were refused in cloud; the Mac jobs did both cleanly). DO: file it in `queue/mac/review/` on the first refusal. DON'T: retry the refused call in cloud.
- **A job reads versions without side effects** (s71, DISC-279: `xcodebuild -version` started Xcode's component install and left the iOS 27.0 runtime unusable on the operator's Mac). DO: `plutil -extract CFBundleShortVersionString raw <app>/Contents/Info.plist`, `defaults read`, `xcrun simctl list runtimes`. DON'T: `xcodebuild` or `softwareupdate` in a job unless the job is for that (`purpose: xcode` in its frontmatter); `mac-job-check.mjs` refuses it otherwise.
- **A Mac job that opens a preview or the site names how the Mac reaches that host** (s76: a job went to hosts described as "public", met the Cloudflare Access sign-in on both and recorded nothing; the vault already held PF-1127 and PF-1210 saying a fresh Mac browser gets the wall). Before filing, grep `queue/mac/done` and the project queue for the host, and write into the job which sign-in it relies on. DO: "reaches preview.example via the operator's signed-in Safari (PF-1127)". DON'T: describe a host as public and queue the job unchecked.
- **A wrap PR carries no `queue/mac/` job without a reviewer verdict on that PR** (s78, DISC-289): the runner runs a `review/` job the moment its PR merges, and s77's wrap merged one marked "not yet reviewed". `merge-review-gate.mjs` now counts a `queue/mac/` file as not notes-only. DO: review the job, then merge. DON'T: let a wrap merge carry an unreviewed Mac job.
