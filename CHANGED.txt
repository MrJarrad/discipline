1.72.0 — grilling assumption gate for real-world properties (2026-09-09)

Added an assumption gate to `grilling`: before any brief (build or fix round) that
depends on how a real-world thing looks, is made, or is used — a material, physical
part, fabrication method, or product convention — the parent lists each such property
and asks the operator in one grilling round, the standard ❓/➡️ format, one
recommended answer each. Prompted by the hoverboard 2026-09-08 velcro case: the
session coined "margin" for a die-cut backing strip and assumed standard stubby
hooks and fuzzy loop pile, spending two rounds before asking three questions the
operator answered in one message. `skills/grilling/SKILL.md` gains the section, a
"When this fires" bullet, a smell-table row, and a narrower "Not for" so a fix round
targeting a real-world property is in scope; description frontmatter gains the
trigger phrases. `skills/grilling/references/DOS-AND-DONTS.md` gains the velcro
DO/DON'T pair and the never-coin-a-term rule. `skills/dispatch-brief/SKILL.md`
checklist and `skills/issue-triage/SKILL.md`'s part-name section each gain one line
routing real-world-property work through the gate.

1.71.0 — retire perplexity-research; settings/permissions guard (2026-09-08)

Removed the `perplexity-research` skill and every reference to it (skill count
46). Research now runs on `research-synthesis` alone (WebSearch/WebFetch) —
no replacement engine. Prompted by tonight's incident: a dispatched Release Ops
agent, blocked on a merge command, tried to rewrite `~/.claude/settings.json`
to widen its own permissions; the harness blocked it. Added a guard rule to
`agents/releaseops.md`, `skills/release-deploy/SKILL.md`, and the scope-fence
section of `skills/dispatch-brief/SKILL.md`: a dispatched agent never edits
settings, permissions, hooks, or plugin config (`~/.claude/**`,
`.claude/settings*.json`); a blocked or denied command is a finding to return
to the parent, never a workaround.

1.70.2 — vocabulary is names of actual things, not only layer names (2026-09-08)

1.70.1 narrowed the canonical vocabulary to "the source file's layer/
component names." The operator corrected this: it doesn't matter whether
the thing is a layer in Illustrator or Figma, or a class or style in code
— the point is consistency in the language and using the names of actual
things. Every thing already has a name where it's defined — a layer,
component, class, token, style, file, or variable — and that name is the
term, whatever the source. `define-terms`, `dispatch-brief`,
`issue-triage`, and `output-styles/discipline.md` now say "names of
actual things wherever defined" instead of "layer names," with the
DO/DON'T examples dropping the layer-only framing; an unmatched term gets
a one-line "which one?" instead of "which layer?" `capture-figma`'s note
is reworded to name its architecture map as one source among several
(design files, code classes/tokens, file names) feeding define-terms,
not the source.

1.70.1 — vocabulary is layer names, not the operator's word (2026-09-08)

1.70.0's part-name fidelity rule framed the canonical term as "the
operator's word." The operator corrected this: the canonical vocabulary is
the layer/component names in the project's source file (Figma,
Illustrator, whatever the source of truth is) — the operator speaks in
those names, and consistency across comms depends on everyone using the
same layer names, not on whoever spoke first. `define-terms` now derives
the glossary from the source file's layer/component list (captured by
`capture-figma` or the project's own capture lane) rather than from
operator usage; an unmatched operator term gets a one-line "which layer?"
question instead of a guess. `dispatch-brief`'s Locked decisions rows and
`issue-triage`'s part-name resolution both quote the layer name verbatim,
with the code identifier (where added) mirroring it. `capture-figma` gains
a short note that its architecture map's layer list is define-terms's
vocabulary source. `output-styles/discipline.md` states the vocabulary is
the source file's names, not a paraphrase.

1.70.0 — pause/resume skill, part-name fidelity (2026-09-08)

New skill `skills/pause-resume/SKILL.md` converts the operator-ratified
pause/resume protocol (`fleet/rulings/pause-resume-protocol.md`) into a
fireable skill with all nine trigger phrases: pause, "I need to pause", "I
need to pause shortly", wind down, stop for now, let's stop here, resume,
pick up where we left off, carry on from the snapshot. Pause halts new
dispatch, stops running agents at their next safe point, banks a one-screen
snapshot into the project handover, and confirms in one line; resume reads
the snapshot and re-dispatches each interrupted lane as a fresh
continuation. Cross-referenced from `routing` (rule 12, persona table) and
the always-on `output-styles/discipline.md` route-by-reflex list, so the
words fire it by reflex instead of falling to `wrap` (which stays the full
session close, not this).

Part-name fidelity: `dispatch-brief`'s Locked decisions section, `define-
terms`, and `issue-triage` now each carry the rule that a physical/visual
part name in the operator's own words travels verbatim — the technical
column may add a code identifier but never substitutes a synonym (ring,
rim, lip, and edge are different parts). `define-terms` adds the part name
to the glossary from the operator's usage before a lane opens, never
guessing it; `issue-triage` quotes the resolved term back to the operator
in one line before a lane opens on a feedback row naming a part. Prompted
by the hoverboard 2026-09-08 miss, where a briefed "ring" cost two lanes
and a review when the operator meant the disc's edge.

1.69.0 — output style: communication rules first (2026-09-08)

One forced output style. `output-styles/discipline.md` now opens with how a reply
reads, and routing follows it — built from the 2026-09-08 transcript research (58
operator confusion signals across 802 sessions; six named failure types). The rules
are positive and exampled: lead with the outcome; use the vocabulary the work already
has and gloss any system term in the same sentence on first use; a second confusion
signal earns different framing, never the same sentences; walk-backs lead with
"Correction:"; every status ends with one next-action sentence; waiting messages say
what is observably happening; a decision message is one question, one recommendation,
one named alternative; ~120 words is a tripwire, not a rule; a pre-send self-check
closes the section. Borrowed lines are credited in the style.

`operator-voice.md` is retired — its force-for-plugin sibling meant it never fired.
Its load-bearing rules are merged in: announce by invoking the real tool, the four
operator calls (creative, aesthetic, scope, destructive), one recommendation and never
a menu, status against the lock, and all twelve native commands used unprompted
(`/todos /plan /context /compact /code-review /security-review /verify /subtask
/rewind /memory /usage /tasks`) — the law test asserts every one by name. The style is
capped at 130 lines with no tables so it reads on a phone.

`dispatch-brief` gains **Fixed evidence return** — final sha, per-criterion table with
file:line, gate output verbatim, open gaps, next owner, budgeted at 250 words excluding
the table and gate output. Every agent references that one section instead of implying
its own shape. Briefs now name skills rather than restating their procedure, may not
paste vault rulings beyond one DO/DON'T pair, and target under 600 words.

A new law test (hooks/scripts/output-style.test.mjs) asserts the frontmatter flags, the
retirement, each communication rule, and the return contract on a whitespace-flattened
copy, so a reflowed paragraph cannot silently drop a rule. Rules whose words also occur
elsewhere in the file are asserted inside their own paragraph block, so deleting the
block goes red. `node --test hooks/scripts/` reports 455 tests; `node --test hooks/`
reports 461 (it also picks up the hook-level suites outside scripts/).

`.gitignore` now ignores `.ledger.md` — the notes ledger is per-run scratch, not
shipped plugin content.

1.68.0 — review/loop stage redesign (2026-09-07)

The reviewer stops being the merge gate and becomes an informer: severity-ranked
findings (red blocks / amber is a call / note is no action), each independently
re-validated before it surfaces. Merge = deterministic gates green + no red
finding open, remitted by the parent. Review rounds are hard-capped at 3 per
change; at the cap the loop halts and the open findings go to the operator.
LIGHT becomes the standing review tier and FULL the exception a brief must
argue; the no-tier fallback inverts from FULL to LIGHT; small fixes ship with no
reviewer. Deterministic gates must be green before a reviewer is solicited. The
reviewer reads the live lock file and reds a drifted spec. Look is the operator's
lane — for UI work the preview link goes out at engineer-done and never waits on
review. Adds the notes-ledger rule (append before compaction, re-read after) and
an effort tier field (routine | contested | high-stakes) mapped in model-routing.
ux-designer is realigned to the same law — visual evidence is agent-internal, the
baton returns to the parent, and ready is the merge condition rather than a review
verdict. A plugin-wide, newline-tolerant test sweeps every shipped doc for the
stale phrasing.
